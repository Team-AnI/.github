# PR Guide (A&I) — PR 작성자용

A&I 프로젝트에서는 **한 PR에 한 목적**을 담고 실제 검증 결과를 공유합니다. 상세 화면 설명은 [PR 실전 가이드](PR_WORKFLOW_GUIDE.md)를 참고하세요.

## 1. PR 생성 전

- [ ] Issue를 만들고 완료 기준을 확인했습니다.
- [ ] 변경 목적이 하나이며 범위가 작습니다.
- [ ] 작업 브랜치와 병합 대상 브랜치를 확인했습니다.
- [ ] 관련 테스트 및 민감 정보 포함 여부를 확인했습니다.

기본 작업 브랜치는 `feature/#12-login`, `fix/#15-auth-error`, `docs/#7-guide`처럼 **유형 + Issue 번호 + 작업 요약**으로 작성합니다. MOAMOA는 개인 Fork에서 작업하고 팀 원본 저장소의 `main`을 대상으로 PR을 만듭니다. 다른 프로젝트는 해당 저장소의 기본 브랜치와 운영 방식을 확인하세요.

## 2. PR 제목

```text
<type>: <subject> (#이슈번호)
```

예: `feat: 로그인 화면 구현 (#12)` · `fix: 예외 처리 수정 (#15)`

커밋 제목도 [공통 커밋 컨벤션](COMMIT_CONVENTION.md)에 따릅니다.

## 3. PR 본문 작성

저장소에 표시되는 템플릿을 우선 사용합니다. A&I [공통 PR 템플릿](../../PULL_REQUEST_TEMPLATE.md)은 다음 항목으로 구성합니다.

| 항목 | 작성 내용 |
| --- | --- |
| 관련 이슈 | `Closes #12`(완료 시 자동 종료) 또는 `Refs #12`(참조만) |
| 작업 내용 | 변경한 이유와 핵심 작업 사항 |
| 테스트·검증 | **실제 실행한** 명령과 결과, 미실행 사유 |
| 스크린샷 | UI 변경 시 Before/After 또는 화면 영상(해당될 경우) |
| 리뷰 요청 사항 | 집중해서 확인받고 싶은 설계·코드 |
| 체크리스트 | 범위, 테스트, 보안, 문서, 셀프 리뷰 확인 |

**실행하지 않은 테스트는 성공했다고 적지 않습니다.** 문서 변경에는 링크·렌더링 확인, UI 변경에는 기기/브라우저 및 화면, API 변경에는 요청·응답 및 테스트 결과, AI 작업에는 재현 명령과 결과가 도움이 됩니다.

## 4. 리뷰 이후

리뷰 요청에 답할 때 변경한 내용과 검증 결과를 구체적으로 남깁니다. 필수 피드백과 테스트를 확인하고, 프로젝트별 승인·CI 조건이 충족된 후에 Merge합니다. MOAMOA 두 저장소는 **최소 1명 Approve 후 작성자가 Merge**하도록 안내합니다.
