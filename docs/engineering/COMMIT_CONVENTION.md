# Git Commit Convention (A&I)

A&I의 기본 커밋 규칙은 MOAMOA Server·Flutter의 협업 방식을 따릅니다. 저장소에 더 구체적인 자동 검사·팀 규칙이 있으면 해당 규칙을 확인합니다.

## 1. 커밋 메시지 형식

```text
<type>: <subject> (#이슈번호)

<body>

<footer>
```

- **type**: 변경 유형, 소문자 사용(필수)
- **subject**: 한글로 간결하게 변경 내용을 요약하고, 50자 이내를 권장합니다. 마침표를 붙이지 않습니다.
- **이슈 번호**: 해당 저장소의 관련 Issue를 `(#12)`처럼 기재합니다.
- **body/footer**: 변경 이유와 종료 키워드 등 필요할 때 작성합니다.

## 2. Type

| Type | 설명 | 예시 |
| --- | --- | --- |
| `feat` | 기능 추가 | `feat: 로그인 화면 구현 (#12)` |
| `fix` | 버그 수정 | `fix: 로그인 실패 처리 수정 (#15)` |
| `refactor` | 동작 변경 없는 구조 개선 | `refactor: 인증 상태 책임 분리 (#20)` |
| `style` | 포맷팅 등 동작 변경 없는 수정 | `style: 코드 포맷 적용 (#21)` |
| `test` | 테스트 추가·수정 | `test: 로그인 실패 테스트 추가 (#23)` |
| `docs` | 문서 수정 | `docs: 기여 가이드 보완 (#1)` |
| `chore` | 빌드·의존성·환경 설정 | `chore: 의존성 업데이트 (#3)` |
| `ci` | CI/CD 변경 | `ci: PR 검사 추가 (#5)` |

MOAMOA Flutter는 UI 중심 작업에 `design`을, 두 MOAMOA 프로젝트는 파일 이동·삭제 등에 `rename`, `remove`를 사용하기도 합니다. **해당 프로젝트에서 정의한 Type을 우선**합니다.

## 3. 작성 시 주의사항

- 한 커밋은 하나의 변경 의도로 작성합니다.
- 본문은 **무엇을 왜 바꿨는지** 필요한 만큼만 설명합니다.
- 관련 Issue가 같은 저장소에 있을 경우 `Closes #12` 또는 `Fixes #12`로 종료를 연결할 수 있습니다. 단순 참조는 `Refs #12`를 사용합니다.
- 비밀 키·토큰·비공개 정보가 포함되지 않았는지 확인합니다.

> PR 제목 규칙은 [PR 작성 가이드](PR_GUIDE.md)를 확인합니다. 프로젝트마다 별도의 제목 검사 워크플로가 있을 수 있습니다.
